# Techzei Magazine Theme 3.2.0 quality gate

The release-quality checks are dependency-free and do not load WordPress. They
are designed to run on PHP 7.4+ and Node.js in CI.

## Local commands

```sh
find . -type f -name '*.php' -print0 | xargs -0 -n1 php -l
node --check assets/js/navigation-fallback.js
php scripts/validate-theme.php
php scripts/test-theme.php
bash scripts/package-theme.sh --version "$(php scripts/validate-theme.php --print-version)" --output /tmp/techzei-magazine-theme.zip
```

`style.css` is the WordPress metadata source of truth for the version. The
validator supports `--expected-version` for a release tag comparison and
`--print-version` for packaging; no release number is hard-coded in the gate.

## What is covered

- Every template and template part has matched block names and nesting, valid
  JSON object attributes, and basic attribute-type checks.
- Settings groups, defaults, sanitization registration, read-only resolver
  behaviour, and ownership/reset wording remain present.
- Image fixtures and source contracts reject `loading="lazy"` combined with
  `fetchpriority="high"`.
- Legacy shortcode registrations and safety primitives are retained, with
  uneven, malformed, nested, and unsafe compatibility fixtures.
- Both explicit article templates remain registered and their precedence guard
  remains in the theme setup source.
- Push/pull-request quality validation is separate from published-release ZIP
  attachment. The package helper requires exactly one top-level theme folder
  containing `style.css`.

The gate is static. WordPress runtime, browser viewport, editor parity,
upgrade, and WP_DEBUG checks remain integration/test-site responsibilities for
the lead agent.
