# 3.4.1 development audit fixes

This development pass keeps the 3.4.1 version unreleased and addresses the
article discovery audit without changing the visual system or Site Editor
ownership.

## Discovery cache behavior

Related, topic, latest-story, and review modules cache bounded post ID lists
for twelve hours. The cache key includes the current post, modified timestamp,
thumbnail, category/tag relationships, relevant settings, taxonomy cache state,
component limits, exclusions, and freshness policy. Only IDs are cached; HTML
is rendered for the current request so admin-bar and user-specific state cannot
leak through a transient.

The cache namespace is bumped when posts, relevant terms, featured images,
Yoast primary categories, or Techzei Settings change. If persistent object
cache is unavailable, the transient fallback remains correct because stale
entries use the old namespace and are ignored.

## Query-count evidence

The former uncached article path could make up to 10–11 bounded editorial
`WP_Query` calls: up to four related-resolution calls, up to three topic calls,
one latest-stories call, one review call, plus rendering queries. The current
uncached path makes at most four module queries in automatic mode (one bounded
related candidate query, one topic candidate query, one latest query, and one
review query); the resolver primes those returned post objects so rendering
does not repeat them. Editorial-first mode can add one bounded editorial
selection query when sticky/editorial IDs are present. Cached ID-list requests
make at most one ordered post query per populated module.

`techzei_tt5_editorial_query_count()` exposes the theme-owned query counter for
the optional WordPress integration suite and Query Monitor comparisons. It is
diagnostic only and does not affect output.

## TOC and overlap behavior

The TOC preserves a valid, unique existing heading ID, normalizes invalid IDs,
and adds deterministic numeric suffixes to duplicates. The rendered H2/H3
markup receives the exact IDs used in the TOC links through
`WP_HTML_Tag_Processor`. The in-flow related module records its selected IDs in
the request, and the sidebar topic module excludes them while still omitting
the current post.

## Release verification boundary

The static checks, PHP 7.4 syntax checks, JavaScript syntax check, theme JSON
validation, block-comment validation, and package-structure validation remain
the normal repository gate. Runtime WordPress tests are optional and require a
separate WordPress test suite; no claim is made that this repository validates
WordPress 7.1.1 yet.
