# Techzei Magazine Theme settings

This document describes the settings track for Techzei Magazine Theme 3.1.0. The implementation is in `inc/settings.php`; the lead agent must load that module from the theme bootstrap during integration.

## Integration

Add this line to `functions.php` with the other theme modules:

```php
require get_theme_file_path( 'inc/settings.php' );
```

The module is safe to load on every request. It registers the Settings API only through `admin_init`, adds the page through `admin_menu`, and does not enqueue frontend assets. Do not duplicate the option schema or settings resolver in `setup.php`, `editorial.php`, templates, or template parts.

The settings page appears at **Appearance → Techzei Settings** for users with the `edit_theme_options` capability. The Site Editor remains the owner of design and content structure.

## Public resolver API

Use the resolver functions below from frontend rendering and editor-preview code:

```php
$settings = techzei_tt5_get_settings();
$homepage = techzei_tt5_get_settings( 'homepage' );
$feed_count = techzei_tt5_get_settings( 'homepage.feed_count' );
$layout = techzei_tt5_get_setting( 'articles', 'default_layout', 'sidebar' );
```

`techzei_tt5_get_settings()` returns the resolved `values` array with these four groups: `header`, `homepage`, `articles`, and `sidebar`. Passing a group returns that group. Passing a dotted path returns one scalar/array value, or `null` when the path is not recognised. `techzei_tt5_get_setting()` supplies an explicit fallback for an unknown path.

The resolver always returns validated defaults on a fresh install and never writes an option during a frontend request. It silently normalizes a damaged database value to a safe allowlisted value; submitted admin values are validated noisily by the Settings API sanitizer.

## Option contract

The only stored option is `techzei_tt5_settings`:

```php
array(
    'version' => 1,
    'values'  => array(
        'header' => array(
            'sticky_desktop' => true,
            'sticky_mobile'  => true,
            'show_search'    => true,
            'show_topics'    => true,
        ),
        'homepage' => array(
            'show_featured_grid' => true,
            'feed_count'         => 8,       // 4–20
            'headline_mode'      => 'marquee', // hidden|static|marquee
            'headline_source'    => 'latest',  // latest|category
            'headline_category'  => 0,       // category term ID
            'headline_count'     => 4,       // 3–8
            'marquee_speed'      => 'slow', // slow|standard
        ),
        'articles' => array(
            'default_layout'     => 'sidebar', // sidebar|no-sidebar
            'automatic_legacy'   => true,
            'show_reading_time'  => true,
            'updated_date'       => 'later', // later|hide
            'author_card'        => true,
            'share_links'        => true,
            'share_destinations' => array( 'x', 'facebook', 'linkedin', 'whatsapp' ),
            'related_stories'    => true,
            'related_count'      => 3,       // 2–6
        ),
        'sidebar' => array(
            'latest_stories' => true,
            'latest_count'   => 5,           // 3–6
            'reviews'        => true,
            'review_category'=> 0,           // category term ID
            'review_count'   => 4,           // 2–6
        ),
    ),
)
```

The fresh-install review category is the category with the `review` slug when one exists. This is resolved without writing defaults. If the selected review category is missing, the Reviews module must be omitted and the settings page displays a warning. The same rule applies to a selected headline category. A selected-category headline source with no valid category remains selected but must omit the strip until the editor corrects it.

Share destinations are stored as fixed-order allowlisted slugs. They are not URLs and cannot be used to inject arbitrary destinations. When `share_links` is false, the frontend should omit the complete share row; when no destinations are selected, it should do the same.

## Ownership and precedence

Techzei Settings owns only the behaviour values in the schema. It does not store or replace:

- Global Styles colours, fonts, widths, or spacing.
- The logo, site title, or tagline.
- Primary, Topics, footer, or social navigation links.
- Footer copy, the India icon, or the builder credit.
- Template and template-part block composition.
- A post's explicit template selection.
- Comments, moderation, archive pagination, static-home selection, or Yoast settings.

An explicitly selected per-post article template takes precedence over `articles.default_layout`. A component removed from a saved Site Editor template takes precedence over an enabled visibility setting; the theme must not recreate the removed component. Frontend consumers should therefore check both the resolved setting and whether their recognised template marker/component is present.

## Security and reset behaviour

The page and the Settings API save path require `edit_theme_options`. The option group capability is explicitly filtered to the same capability. WordPress's Settings API option nonce protects normal saves; the separate reset form has its own `techzei_tt5_restore_defaults` nonce and `admin_post` handler.

The **Restore Techzei defaults** action deletes only `techzei_tt5_settings`. The resolver then serves fresh defaults. It does not reset posts, media, menus, templates, template parts, Global Styles, comments, Yoast, or plugin settings. The reset action is intentionally separate from Save changes and requires confirmation plus a server-side nonce/capability check.

All enum values, booleans, bounded counts, share slugs, and category term IDs are sanitized. No arbitrary URL, CSS, PHP, JavaScript, image-size, SEO, or breakpoint setting is accepted.

## Lead-agent checks

After wiring the module, verify the following in a WordPress test site:

1. Fresh install shows the documented defaults without creating the option until Save changes is used.
2. A user lacking `edit_theme_options` cannot see or save the page; invalid save and reset nonces are rejected.
3. Every field saves and reloads, including unchecked checkboxes and an empty share-destination set.
4. Disabled dependent fields preserve their previous values when their parent is turned off, then restore those values when re-enabled.
5. Missing headline/review categories produce warnings and do not silently substitute another category.
6. Restore Techzei defaults removes only the Techzei option and leaves Site Editor customizations and content unchanged.
7. Frontend consumers use one resolver source and do not call `update_option`, `add_option`, or duplicate settings logic.
