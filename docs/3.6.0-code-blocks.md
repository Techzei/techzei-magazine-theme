# Theme code-block compatibility (3.6.0)

The theme provides a small, self-hosted Prism.js renderer for Enlighter code
shortcodes and saved code blocks. It does not edit stored posts. While Enlighter
defines `ENLIGHTER_VERSION`, the theme does not register its compatibility
filters, shortcode or code assets. After Enlighter is deactivated, saved
`[enlighter]` shortcodes, Enlighter Gutenberg blocks, inline Enlighter code,
core Code blocks and core Preformatted blocks render using theme markup. Legacy
plain `<pre>` and Crayon-style `<pre>` markup is intentionally left unchanged.

Code assets are enqueued on singular posts only when the saved content contains
a supported code marker. The content renderer also requests assets when it
encounters a code block. Inline Enlighter code needs only the stylesheet. The
copy control is created by JavaScript, so it is absent when JavaScript is
disabled. Code stays escaped and readable in the existing dark monospace
surface without JavaScript or when a language grammar is not shipped.
The readable script source is `assets/js/code-blocks.js`; its checked-in
minified counterpart is what the theme enqueues.

With gzip level 9 in the local measurement, the base bundle is 8,695 bytes,
the code stylesheet is 882 bytes, and the copy runtime is 897 bytes. A Bash or
JSON code page therefore adds about 10.2 KiB compressed. Optional grammars are
loaded only when present. The requested PHP grammar plus markup-templating
adds 2,539 bytes, taking a PHP page to about 12.7 KiB compressed. That exceeds
the aspirational 12 KB ceiling for PHP pages; the current supplied editorial
inventory uses Bash and JSON, which stays within budget. Revisit that budget
if PHP examples become common rather than silently omitting the requested PHP
grammar.

## Supported grammars

The Prism 1.30.0 base bundle includes markup, clike, JavaScript, Bash and JSON.
Local optional grammars included with the theme are TypeScript, CSS, Python,
YAML, Diff, INI and PHP. PHP loads the local markup-templating dependency first.
Aliases such as `shell`, `sh`, `js`, `html`, `xml`, `ts`, `py` and `yml` map to
their shipped grammar. Unsupported or unknown language names fall back to
plain text without attempting to fetch a file.

To add a grammar, include its minified Prism 1.30.0 component under
`assets/vendor/prism/components/`, add its aliases, display label, file name
and dependency chain in `techzei_tt5_code_languages()` in
`inc/code-blocks.php`, then test dependency ordering and the ZIP contents.
Never load Prism components from a CDN or use the Prism autoloader.

## Rollback

Reactivate Enlighter. Its `ENLIGHTER_VERSION` constant makes the theme feature
dormant automatically. If Enlighter must stay inactive, a site-specific
must-use plugin can disable the theme feature with:

```php
add_filter( 'techzei_tt5_code_blocks_enabled', '__return_false' );
```

The feature is render-time only. It does not rewrite posts or require a
database rollback. Keep Enlighter installed but inactive during the agreed
observation period before considering deletion.

## Staging rollout checklist

1. Keep Enlighter active and confirm its existing rendering is unchanged. The
   theme feature must register no Enlighter shortcode and enqueue no code
   assets while `ENLIGHTER_VERSION` is defined.
2. Deactivate, but do not delete, Enlighter. Check an Enlighter shortcode with
   Bash, JSON, no `lang`, multiline and one-line examples; an old
   `enlighter/codeblock`; inline Enlighter code; core Code; and core
   Preformatted blocks.
3. Compare the code text, including `$schema`, quotes, `<name>`, `&&`, blank
   lines, indentation and trailing spaces. Confirm there is one Copy control
   on blocks, none on inline code, and no Enlighter toolbar, class or shortcode
   text in output, excerpts or feeds.
4. Check the existing core Code article and the six legacy plain/Crayon-style
   `<pre>` articles named in the release task. The latter must remain visually
   unchanged.
5. Check keyboard focus and copy feedback, the clipboard path and the
   fallback path, no-JavaScript rendering, print view, 360px and desktop
   widths. Long lines should scroll within their code block, not the page.
6. Inspect the network panel on the homepage, an archive, search, a normal
   article and a code article. Pages without code must have no theme code
   assets; the code article should load only local assets and grammars it uses.
7. After staging sign-off, upload the 3.6.0 ZIP to production with 3.5.16
   available for rollback. Deactivate Enlighter only after confirming the
   theme is active, purge page cache, and repeat the relevant checks. Keep
   Enlighter installed but inactive during the agreed observation window.

## Verification limits

The repository includes dependency-free fixture checks for shortcode
protection/restoration, block conversion, escaping, language fallback and
conditional asset detection. Full browser checks, plugin-active/inactive
comparison, clipboard testing on Safari/iOS and a staging or production
rollout require a WordPress site. Those checks are not implied by passing the
repository test scripts.
