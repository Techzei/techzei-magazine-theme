# Version 3.5.16 typography verification notes

Based on `main` at `03de48c` (3.5.15), verified against `origin/main` on
2026-10-08. These notes document the CSS candidate comparisons and their limits.
The production smoke check was against the previously installed theme, not this
3.5.16 package; no production settings, templates, content or files were changed.

## Scope and decisions

- Keep Georgia headlines/prose, system-sans controls, Reading Charcoal
  `#575555`, existing title sizes and article/sidebar widths.
- Article-title tracking changes from `-0.06em` to `-0.025em`, with `1.1`
  leading; legacy title tracking also relaxes without changing its size.
- Featured headlines use `1.12` leading; secondary cards use `1.15` and a
  20px minimum instead of 17.6px. Existing cards remain the same height.
- Metadata is 12.48px at a 16px root size, without opacity reduction. Homepage
  sidebar and article discovery dates use the same scale. Featured dates are
  light paper-colour text over the existing dark gradient.
- Prose is 19px desktop / 18px mobile at `1.68` leading. Explicitly authored
  WordPress block styles retain the existing cascade; no Global Styles reset.
- Table text is 15px at `1.5` leading. Override inherited `overflow-wrap:
  anywhere` with normal wrapping in tables; keep horizontal overflow local to
  the table. No `overflow-x: hidden` workaround, new JavaScript or PHP filter.
- Do not change embedded text in featured images, discovery selection,
  templates, shortcodes, SEO, sharing, navigation behavior or global font
  weight.
- The mobile menu's core WordPress SVG is a two-stroke mark. Hide only that
  decorative SVG and draw a three-line CSS glyph on the same core button; the
  button label, menu behavior, focus handling and close icon remain core-owned.

## Visual and measured evidence

Public logged-out HTML was downloaded for the homepage, recent camera-phone
guide, recent OpenCode article (sidebar), 2016 Narendra Modi article (legacy),
Phones archive, an iPhone search and a real 404 response. Local previews retain
the live WordPress styles and markup, substituting baseline or candidate theme
CSS. The core Navigation/Interactivity modules were mirrored unchanged locally
to avoid cross-origin module restrictions. This is a CSS/interaction preview,
**not a local WordPress installation or a production deployment test**.

Screenshots and JSON measurements are saved locally under
`dist/typography-3.5.16/` and excluded from the theme ZIP. Comparison screenshots
cover desktop article opening/prose, mobile article opening, mobile featured
cards, and matching price-table views.

The visual comparisons support the change: letterforms are less compressed,
headline lines have clearer separation, supporting cards are easier to scan,
and prices can be read without reconstructing digits. Body line height remains
almost unchanged on mobile despite the larger letters.

## Regression checks

- Browser probe across seven page types at 320, 375, 768, 1024 and 1280px:
  no newly introduced document overflow, clipped featured-copy boxes or
  lazy/high-priority image conflicts. All 20 tested currency cells (four per
  viewport) stay on one line.
- Before/after main-content text matched on all 14 paired mobile/desktop
  page snapshots. No editorial content changed.
- Search opens with expanded state and focus in the search field; Escape
  closes it and returns focus to its toggle.
- Core mobile Navigation opens, closes with Escape, and returns focus to the
  Open menu button. The closed-state button visibly has three lines and the
  open-state close icon remains unchanged. No replacement navigation
  implementation was added.
- Search remains visible and usable with all scripts removed from the local
  snapshot, without horizontal page overflow at 375px.
- Sticky header remains at the viewport top; the article sidebar remains
  sticky on desktop. WhatsApp remains first in the mobile share dock.
- A normal TOC link targets its matching heading. This is not exhaustive TOC
  anchor coverage; the PHP anchor implementation is unchanged.
- All existing static/theme/settings/editorial checks pass, along with PHP
  lint, JavaScript syntax checks, JSON validation and `git diff --check`.

### Known pre-existing limitation

At 320px the 404 search form makes the page 338px wide in **both** baseline and
candidate. This is the only overflow failure in the 35-case candidate matrix.
It is not introduced by typography and is intentionally not fixed in this
focused update. The 404 fits at the other four tested widths.
