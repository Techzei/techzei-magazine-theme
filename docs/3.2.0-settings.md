# Techzei Magazine Theme 3.2.0 settings

This reference supplements the 3.1.0 settings contract. The implementation remains in `inc/settings.php`, with the single versioned option `techzei_tt5_settings` and the same `edit_theme_options` capability and nonce protections.

## New behaviour controls

The 3.2.0 schema preserves every 3.1.0 value and adds:

```php
'articles' => array(
    'related_mode' => 'automatic', // automatic|editorial-first
),
'sidebar' => array(
    'mobile_discovery' => true, // show the article discovery sidebar on mobile
),
```

`automatic` is the fresh-install default and keeps the existing deterministic related-story behavior. `editorial-first` is an allowlisted hand-off mode: the editorial consumer may provide an ordered set first and should fill any remaining slots with the existing automatic relevance query. The settings module does not store post IDs, rewrite content, or implement editorial selection itself.

`mobile_discovery` is a behavior default for the recognized article discovery sidebar. A frontend consumer must apply it only at its mobile breakpoint and must continue to respect an explicitly selected no-sidebar article template and saved Site Editor composition.

## Resolver cache

`techzei_tt5_get_settings()` and `techzei_tt5_get_setting()` share one normalized, request-local resolved-settings cache. The cache is invalidated when the namespaced option is added, updated, or deleted, and at the start of the sanitizer. It is not a persistent/object cache and does not purge plugin, page, object, or CDN caches.

## Read-only diagnostics

Appearance → Techzei Settings reports the active theme and parent theme versions. It also inspects WordPress’s block-template registry and lists saved custom `wp_template` and `wp_template_part` entries for the active theme, each with an **Inspect in Site Editor** link. Theme-file templates are not labelled as saved customizations. The diagnostics perform no save, delete, reset, or template-content operation.

## Integration assumptions and checks

- `functions.php` loads `inc/settings.php` before consumers that call the resolver; the current bootstrap already satisfies this order.
- The setup/frontend workstream should read `sidebar.mobile_discovery` and add the corresponding mobile-only behavior to the recognized discovery-sidebar marker. It must not recreate a component removed in a saved template.
- The editorial workstream should read `articles.related_mode`; `editorial-first` must remain deterministic, exclude the current post, and fall back only to the agreed automatic relevance query.
- The existing scoped reset deletes only `techzei_tt5_settings`; it must remain separate from Site Editor/template operations.

Focused checks should cover fresh defaults without an option write, all new values saving and reloading, invalid enum rejection, cache invalidation after add/update/delete, capability and nonce failures, and diagnostics that leave saved templates and content unchanged.
