# Techzei Magazine Theme — 3.1.0 scope

Status: proposed implementation scope. No implementation or deployment is included in this document change.

Baseline: release `v3.0.0`, commit `df92ddc`.

## Objective

Make the theme easier to edit, more consistent across screen sizes, and more efficient to render while retaining Techzei's logo, soft cyan/lime identity, magazine homepage, and support for Valenti-era posts.

An editor should be able to change the publication's colours, reading width, navigation, and article layout through WordPress without editing PHP or CSS. A reader should get a stable header, readable article layout, accessible controls, and appropriately sized images.

This release covers theme templates, template parts, patterns, PHP, CSS, JavaScript, `theme.json`, an Appearance > Techzei Settings page, documentation, verification, and release packaging.

## Scope boundaries

Excluded: hosting/CDN configuration, page-cache plugins, Yoast configuration, rewriting articles, fixing attachment metadata in the database, changing social accounts, analytics/popularity tracking, and bulk thumbnail regeneration.

Production deployment is a separate operation after the candidate package passes acceptance checks. The theme must not reset saved Site Editor customisations or rewrite existing posts during activation or upgrade.

## 1. Make theme settings control the actual design

Priority: required foundation.

Current code defines the same colours and widths in `theme.json` and hard-coded CSS variables. Many components also hard-code Georgia and pixel widths. Custom styles are enqueued on the frontend without an equivalent editor stylesheet path. These arrangements can make editor settings and previews diverge from the published result.

Deliverables:

- Use WordPress preset variables for brand colours, text colours, fonts, and content/wide widths. Keep explicit component limits only where the layout requires them.
- Define separate readable text accents for light and dark backgrounds. Use a light accent for the footer section labels; the current dark teal on dark footer measures approximately 2.85:1.
- Load the relevant component and article styles into the Site Editor and post editor using supported WordPress mechanisms. Scope frontend-only rules, including sticky positioning and page overflow, away from editor controls.
- Standardise the spacing scale, mobile gutters, button dimensions, border treatment, and heading hierarchy.
- Preserve current default branding and familiar page structure.

Acceptance:

- Changing the accent, font, or content width in Global Styles changes the intended components in both editor and frontend.
- The default palette meets 4.5:1 contrast for normal text and 3:1 for large text and applicable interface boundaries/focus indicators.
- Editor controls remain usable and no custom styling leaks into the WordPress administration interface.
- At 320px width, all reading content has consistent gutters and long titles wrap without horizontal page scrolling.

## 2. Consolidate image rendering and priority logic

Priority: required performance fix.

The current featured-image filters separately modify loading, priority, alt text, and sizes. Non-hero images are forced to lazy-load without removing a pre-existing high fetch priority. The same hero size hint is also used for a homepage column and a full-width article image, even though their display widths differ.

Deliverables:

- Consolidate image attribute handling around `WP_HTML_Tag_Processor` and clearly identified image roles: homepage lead, homepage tile, list card, article hero, and small discovery thumbnail.
- Preserve WordPress's useful loading decisions where possible. Explicitly prevent lazy/high-priority combinations and avoid assigning high priority merely because a particular image size was chosen.
- Calculate responsive `sizes` from the component's actual layout and breakpoints.
- Preserve meaningful existing alt text and safely handle fallback titles containing quotes, ampersands, entities, and replacement-like text such as `$0`.
- Provide clean no-image states for cards and story lists; text must not be stranded in a narrow thumbnail column.
- Reuse the existing registered crops unless measurements demonstrate a worthwhile missing size. Do not silently introduce another regeneration requirement.

Acceptance:

- A page has at most one image explicitly promoted by the theme to high priority.
- Below-fold images retain lazy loading, dimensions, and valid responsive attributes.
- No image has both `loading="lazy"` and `fetchpriority="high"`.
- Browser-selected image sources are reasonable for the rendered width and device pixel ratio on the tested screens.
- Special-character alt text remains one valid attribute; missing thumbnails produce a readable layout.

## 3. Complete header, search, and navigation behaviour

Priority: required interaction fix.

Deliverables:

- Retain the sticky outer header and account for the WordPress admin bar, viewport changes, and the sticky sidebar's offset.
- Keep the logo visible on mobile and use the compact search icon to open the search field.
- Represent the search control explicitly in block markup, associate it with the search region, and maintain its accessible name and expanded state.
- Return focus to the search toggle when Escape closes a search field that holds focus. Close on an outside click without stealing focus from the clicked control.
- Ensure the mobile menu and search do not obscure each other's controls or leave hidden focusable elements behind.
- Preserve WordPress Navigation block behaviour for opening, closing, keyboard navigation, and focus management.
- Give navigation regions meaningful names such as Primary, Topics, Explore, Company, and Connect.
- Avoid collisions if an editor adds another header/search instance in a preview or template.

Acceptance:

- Logged-out readers can open the menu, navigate to an item, close it, and reopen it at 320px and 375px without delays.
- Search opens, focuses the input, submits to native WordPress search, and closes correctly with Escape and outside clicks.
- Header and sidebar content remain reachable during scrolling; neither sits underneath the other.
- Search remains available when JavaScript is unavailable. The no-JavaScript navigation behaviour is explicitly checked and documented.
- Keyboard focus is visible and is never left inside a hidden search panel.

## 4. Replace the ticker's perpetual interval

Priority: required interaction and accessibility fix.

Deliverables:

- Replace the 45ms `setInterval` loop with a controlled animation implementation.
- Keep a smooth desktop marquee option, reflecting the requested newspaper behaviour. Provide a visible Pause/Resume control and pause while a reader interacts with a headline.
- Use a static, horizontally swipeable list on mobile and when reduced motion is requested.
- Suspend animation when the ticker is outside the viewport or the document is hidden. Respond to resizing and motion-preference changes.
- Keep one accessible, keyboard-reachable instance of every headline. Any visual copies used for a seamless loop must be hidden from assistive technology and tab order.

Acceptance:

- No continuously running interval drives the ticker.
- Pause/Resume works by keyboard and touch, and reduced-motion mode does not animate.
- Every headline is readable and reachable without waiting for animation.
- Resizing does not produce a broken loop, unexpected page overflow, or a trapped scroll gesture.

## 5. Provide explicit article layouts

Priority: required theme capability.

The current legacy/current distinction is an automatic body class based on shortcodes or a pre-2024 publication date. Both modes still use one single-post template with a sidebar. This does not provide the full-width versus sidebar choice previously requested.

Deliverables:

- Keep Automatic as the default so existing posts retain their current legacy/current treatment.
- Register editor-selectable post templates for Article with sidebar and Article without sidebar. The latter should have a wider media area with a comfortable text reading width, rather than edge-to-edge paragraphs.
- Provide a simple legacy-style override for exceptions if the two explicit templates do not cover the necessary cases. Prefer native template selection before introducing a custom settings panel.
- Keep title, metadata, hero, sharing, author profile, related stories, and comments coherent across both layouts.
- Show an Updated date only when it conveys a later date than publication.
- Avoid empty spacing when comments, biographies, tags, related stories, or featured images are absent.
- Keep ordinary pages free of visible breadcrumbs.

Acceptance:

- An editor can select a sidebar or no-sidebar layout without changing post content or writing code.
- Existing posts keep their default treatment after upgrading.
- Long titles, absent images, absent bios, closed comments, and short articles remain balanced on mobile and desktop.
- The hero and article content follow the title and metadata without excessive empty space.

## 6. Strengthen homepage and listing templates

Priority: required template consistency.

Deliverables:

- Add one accessible homepage H1 without restoring the large promotional masthead the user removed.
- Check hero/tile/feed queries together, including fixed offsets, sticky-post handling, empty states, and pagination.
- Ensure next/previous pagination changes the intended feed and does not repeat or omit stories because of an incorrect offset.
- Correct labels generated by theme modules: a core Latest Posts block must not be presented as measured Popular or Trending content without a corresponding data source. Use a truthful default label; keep labels editable.
- Make the Topics navigation a clearly named, removable template part with a documented placement. Preserve the primary menu independently.
- Align archive, search, home/index fallback, and 404 spacing and typography with the same design tokens.
- Provide a readable card layout when a result has no thumbnail or a particularly long title.

Acceptance:

- Homepage, archive, search results, empty search, 404, and paginated lists have a coherent heading structure and usable navigation.
- Homepage feed pagination is checked through at least three pages with a known post set.
- Template labels describe the query behaviour accurately.
- Removing Topics through Site Editor leaves no empty separator or spacing block.

## 7. Make editorial modules predictable and efficient

Priority: required behaviour review; caching is conditional.

Deliverables:

- Review latest, reviews, and related-post queries for predictable ordering, current-post exclusion, empty results, and unnecessary repeat work.
- Preserve `no_found_rows` and appropriate WordPress query caching. Measure the module cost on an uncached request before adding another cache layer.
- Add fragment/result caching only if that measurement justifies it, with explicit invalidation for publication, edits, deletions, category changes, and thumbnail changes. Do not cache personalised/admin-only output into public pages.
- Make review category, module item counts, and share destinations configurable through the Techzei Settings controls defined in section 10. Keep placement and visual composition in Site Editor; avoid independent controls for the same value in both interfaces.
- Keep shortcodes needed by existing templates working during any conversion to native blocks or patterns.
- Correct reading-time counting so shortcode syntax does not inflate the estimate; retain a sensible fallback for empty content.

Acceptance:

- Modules never include the current article in its own recommendations.
- Empty modules do not leave orphaned headings or borders.
- Publishing/editing a relevant post updates module output without a manual theme-cache purge.
- Any caching change includes a measured benefit and an invalidation check.

## 8. Preserve legacy content safely

Priority: release compatibility gate.

Deliverables:

- Retain support for column, alert, button, pullquote, hr, and attention shortcodes.
- Verify first/middle/last column combinations, unequal columns, missing closing tags, nested formatting, and old attribute spellings or quoted forms actually present in the compatibility fixtures.
- Keep each shortcode's returned markup self-contained so malformed content cannot leave the surrounding article wrapper open.
- Preserve links, nested content, alignment intent, and safe URL/attribute handling.
- Avoid changing stored post content as part of theme rendering or activation.

Acceptance:

- Valid half/half and third/two-thirds layouts sit side by side when space permits and stack cleanly on narrow screens.
- Malformed input degrades into readable content without corrupting the footer or neighbouring blocks.
- Existing shortcode names continue to resolve after the upgrade.
- Unsafe link schemes and attribute injection remain blocked.

## 9. Clean up theme ownership and compatibility

Priority: required maintenance work.

Deliverables:

- Own the presentation of comments and post navigation through Techzei patterns/wrappers while retaining native WordPress blocks. Review the existing parent-pattern references before replacing them; retain core accessibility and pagination behaviour.
- Remove the unused newsletter template part, obsolete menu-lock selectors, and demonstrably unreachable styles. Confirm references before deleting anything.
- Format compressed template markup so reviews and future edits are practical.
- Consolidate duplicate article rules and replace stale file comments, including the JavaScript file description that still calls it a navigation fallback.
- Use consistent Techzei Magazine naming for new/internal implementation. Preserve existing public `techzei_tt5_*` filters and any documented integration points, or provide compatibility aliases; a cosmetic rename must not break integrations.
- Review hard-coded navigation URLs for root and subdirectory installations. Document which links an editor must select for their own site and avoid destructive automatic menu creation.
- Keep translatable PHP strings under the existing text domain. Put new pattern text in a form WordPress can translate.
- Retain the SEO-provider detection guard; verify that the theme emits no duplicate metadata when Yoast is active. No Yoast setting changes are part of this work.

Acceptance:

- Required parent-theme installation remains correctly declared and documented.
- Theme-owned pattern changes produce no invalid-block warnings on opening and saving templates.
- Existing integration hooks and shortcode names remain compatible.
- No unused newsletter component remains in the candidate package.

## 10. Add a focused Techzei Settings page

Priority: required theme capability.

Add Appearance > Techzei Settings for theme behaviour and publication-wide defaults. Use a lightweight WordPress administration page with ordinary labelled fields, short explanations, and a Save changes action. Group the controls into Header, Homepage, Articles, and Sidebar sections on one page. The frontend must not acquire an additional JavaScript framework for this feature.

The tables below are the agreed settings inventory for 3.1.0. Defaults describe a fresh installation or an option that has never been saved. Upgrades preserve previously saved supported choices and customised templates.

### Header controls

| Control | Allowed values | Default | Behaviour |
| --- | --- | --- | --- |
| Sticky header | Independent Desktop/tablet and Mobile checkboxes; split at the theme's mobile breakpoint | Both on | Controls whether the header remains visible while scrolling. Off leaves it in normal document flow. Sidebar offsets follow the active header mode. |
| Header search | Show / Hide | Show | Controls the theme's desktop search and mobile search toggle together. Search remains available through the native search route and search-results template when hidden here. |
| Topics navigation | Show / Hide | Show | Controls the secondary Explore topics component wherever the theme places it; it does not modify the primary menu or its links. |

### Homepage controls

| Control | Allowed values | Default | Behaviour |
| --- | --- | --- | --- |
| Featured stories grid | Show / Hide | Show | Shows the existing one-lead/four-tile composition. Hiding it removes the complete section and returns those posts to the main feed. |
| Stories per feed page | Integer 4–20 | 8 | Applies to the theme's homepage feed only. It does not overwrite WordPress Reading settings or archive/search pagination. |
| Headline strip | Hidden / Static list / Desktop marquee | Desktop marquee | Desktop marquee includes Pause/Resume. Mobile and reduced-motion readers always receive the static list. |
| Headline source | Latest published posts / Selected category | Latest published posts | The category selector is enabled only for Selected category. No popularity tracking or popularity claim is implied. |
| Headline category | One existing WordPress category | None | Required when Selected category is chosen. If it becomes unavailable, show an admin notice and omit the strip until corrected, rather than silently changing its source. |
| Headline count | Integer 3–8 | 4 | Controls the number of unique headlines. Visual animation copies do not count as additional items. |
| Marquee speed | Slow / Standard | Slow | Maps to documented, restrained animation presets; relevant only to desktop marquee mode. Readers retain the pause control. |

Keep the headline label editable in Site Editor, with a truthful default such as Latest headlines. A changed post count must recalculate hero/feed exclusion and pagination; do not merely change the block's perPage value while leaving fixed offsets behind.

### Article controls

| Control | Allowed values | Default | Behaviour |
| --- | --- | --- | --- |
| Default article layout | With sidebar / Without sidebar | With sidebar | Applies to posts using the default template. An explicitly selected per-post template takes precedence. |
| Automatic legacy styling | On / Off | On | Retains the established shortcode/date detection for typography and spacing. It does not override a selected sidebar/no-sidebar template or turn off shortcode support. |
| Reading time | Show / Hide | Show | Controls the reading-time item in article metadata. |
| Updated date | Show when later / Hide | Show when later | Avoids repeating the publication date as an identical update date. |
| Author profile card | Show / Hide | Show | Controls the card below the article. The title-area author byline remains present. Missing biographies produce a compact name/avatar card without empty biography space. |
| Share links | Show / Hide | Show | Controls the theme's article share row. |
| Share destinations | Checkboxes: X, Facebook, LinkedIn, WhatsApp | All four selected | Uses a fixed display order and the existing safe share URLs. With no destinations selected, omit the entire row. |
| Related stories | Show / Hide | Show | Controls the related-story module; recommendations use shared categories and exclude the current post. |
| Related story count | Integer 2–6 | 3 | Sets the maximum number of related stories; fewer results are allowed. No unrelated fallback is inserted merely to reach the count. |

### Article sidebar controls

| Control | Allowed values | Default | Behaviour |
| --- | --- | --- | --- |
| Latest stories module | Show / Hide | Show | Controls this module within article sidebars. It has no effect when the article has no sidebar. |
| Latest story count | Integer 3–6 | 5 | Maximum number of latest stories, excluding the current post. |
| Reviews module | Show / Hide | Show when a review category resolves | Controls the review discovery module. |
| Review category | One existing WordPress category | Category matching the current `review` slug, when present | Store the selected term ID. If none resolves or the term is deleted, omit the reviews module and explain the missing selection in settings. Do not substitute all posts. |
| Review count | Integer 2–6 | 4 | Maximum number of reviews, excluding the current post. |

Empty or disabled modules must not leave orphaned headings, borders, or padding. If both sidebar modules are disabled, the editor receives a short explanation that selecting Without sidebar is the way to reclaim the layout space; the theme does not silently change the chosen article template.

### Settings that stay in existing WordPress screens

Provide labelled shortcut links from Techzei Settings to the relevant editor screens, with these clear ownership rules:

| Setting | Where it belongs |
| --- | --- |
| Colours, font families, typography sizes, content/wide widths, spacing | Site Editor > Styles |
| Logo, site title, tagline | WordPress site identity blocks/settings |
| Primary, Topics, and footer navigation links; social profile URLs | Site Editor > Navigation / corresponding template parts |
| Footer copy, India icon/credit, and builder credit | Site Editor > Footer |
| Block placement, header/footer composition, section labels | Site Editor > Templates and template parts |
| One post's explicit layout | Post editor > Template |
| Comment availability and moderation | WordPress Discussion settings and individual post settings |
| Archive page size and static homepage selection | WordPress Reading settings |

Do not add controls for raw CSS/PHP/JavaScript, SEO metadata, image crop dimensions, lazy-loading disable switches, arbitrary per-device breakpoints, or compatibility-shortcode disable switches. Keep those implementation details reliable by default. Footer editing remains available in Site Editor; no second copy of footer text is stored on this page.

### Precedence, storage, and upgrade behaviour

- Use one namespaced, versioned options structure registered through the WordPress Settings API. Defaults work without writing settings during activation or frontend requests.
- Keep the permission required to view and save settings consistent with `edit_theme_options`, and account for the Settings API save capability explicitly. Verify capability and nonce checks on save and reset.
- Validate booleans, bounded integers, allowlisted modes, share destinations, and category IDs. Report invalid values clearly; do not store executable input or arbitrary URLs in these controls.
- Site defaults apply only to recognised Techzei components. Never globally rewrite every core Query, Navigation, Image, or Columns block to enforce these choices.
- A per-post template choice wins over Default article layout. Site Editor owns structure and visual styles; the settings page owns the behaviour values listed above.
- Removing a component in Site Editor takes precedence over enabling it here: the theme must not recreate deleted blocks. Explain this beside visibility controls and provide an Open template shortcut.
- Use one resolved settings source in frontend rendering and editor previews so counts and toggles cannot disagree. Avoid a duplicate local block setting for a global option; direct users to Techzei Settings where appropriate.
- Existing saved templates that lack the updated component markers must be detected or explicitly accounted for in upgrade guidance. Do not claim a setting applied successfully to an unsupported custom template.
- On save, invalidate only theme-owned caches affected by the changed setting, if such caches exist. Do not purge unrelated plugins or CDN caches.
- Add Restore Techzei defaults as a separate confirmation action. It resets only this options structure, never Global Styles, menus, templates, content, attachment metadata, or plugin settings.
- Provide read-only theme/parent versions and a documentation link. Export/import tooling and a custom live-preview application are deferred beyond 3.1.0.

Acceptance:

- All listed settings can be saved, reloaded, and observed in their intended component, including the editor preview where applicable.
- Controls whose dependencies are disabled are hidden or disabled with an explanation; keyboard and screen-reader users can understand the form and save notices.
- Users without the required capability cannot save settings, and a request with an invalid nonce is rejected.
- Changing the featured-grid toggle or feed count passes the three-page pagination check without duplicate or omitted posts.
- An explicitly selected article template is not overridden by a global layout change.
- Reset affects only Techzei settings; upgrade and theme switching preserve content, templates, menus, and customisation data.
- The settings page introduces no extra frontend assets solely for administration.

## 11. Verification and release deliverables

The implementation should produce one reviewable candidate ZIP, a changelog, updated setup/upgrade guidance, and a short verification record that identifies the WordPress/PHP versions and browser configurations actually exercised.

Verification matrix:

| Area | Required coverage |
| --- | --- |
| Templates | Homepage, sidebar article, no-sidebar article, legacy article, page, category/archive, search with/without results, 404, feed pagination |
| Viewports | 320px, 375px, 768px, 1024px, 1440px; 200% zoom for header and article controls |
| Interaction | Logged-out menu/search, keyboard focus, Escape, sticky header/sidebar, ticker pause, reduced motion, no JavaScript |
| Content cases | Long title, no thumbnail, no author bio, no related posts, comments closed, wide table, embed, code block, legacy columns |
| Editor | Global Styles colours/fonts/widths, template switching, navigation editing, save/reopen without invalid-block warnings |
| Theme settings | Every control and dependency, default values, save/reload, validation, role/nonce checks, per-post precedence, removed/custom components, scoped reset |
| PHP/rendering | Syntax checks, supported PHP syntax, safe image attributes, shortcode escaping, image-priority invariants, no PHP notices under WP_DEBUG |
| Upgrade | Fresh install and 3.0.0 upgrade, including a site with saved template/template-part customisations |
| Packaging | One top-level theme directory, required files present, theme/version/tag match, valid ZIP, no secrets or development artifacts |

Use focused regression tests for image rewriting, legacy markup, and any new stateful behaviour. Add browser checks for the concrete interaction and layout risks. Avoid tests that merely repeat static implementation details.

Update the existing release workflow to run the necessary validation before attaching the ZIP and exclude development-only files introduced by this work. Verify the build without publishing a production release as a side effect of testing.

Update `Tested up to` only to a WordPress version that has actually passed the agreed checks. Regenerate `screenshot.png` from the completed default design if the candidate's appearance changes materially.

## Delivery order

1. Establish design tokens, editor/frontend style parity, and the settings schema with its precedence rules.
2. Build Techzei Settings and connect image/header/search/ticker behaviour to the applicable controls.
3. Add article template choices and verify homepage/list pagination, visibility controls, and empty states.
4. Connect editorial-module controls, profile their runtime cost, and run legacy compatibility cases.
5. Complete cleanup, upgrade guidance, and focused regression checks.
6. Build and review the 3.1.0 candidate; publish and deploy through the established release process when approved.

## Definition of done

- Required deliverables above pass their acceptance checks, or a specific unresolved item is recorded before release.
- An editor can change the supported design settings and article layout with a matching frontend result.
- Appearance > Techzei Settings implements the agreed control inventory without duplicating Site Editor or core/plugin settings.
- Previously published posts and saved editor customisations survive the upgrade.
- No known theme regression remains in mobile navigation, image priority, contrast, template pagination, or supported legacy shortcodes.
- The final report distinguishes completed checks from any environment-dependent checks still awaiting verification.
- A validated, installable candidate ZIP and clear upgrade/rollback instructions are available. Rollback uses the retained 3.0.0 package and an export/backup of any changed editor customisations.
